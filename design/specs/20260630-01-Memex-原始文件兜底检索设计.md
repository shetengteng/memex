# Memex 原始文件兜底检索设计（raw_grep / raw_find / raw_read）

- 日期：2026-06-30
- 状态：草案，待评审
- 作者：terrell.she

## 1. 背景

当前 memex 的所有跨会话检索（`search_memory` / `get_project_context` /
`list_sessions_by_range` 等 MCP 工具）统一走 SQLite **FTS5 全文索引**：

- 入口：`crates/memex-core/src/retriever/mod.rs` → `Retriever::search_filtered`
- 索引：`crates/memex-core/src/storage/db/schema.rs` 中的 `chunks_fts USING fts5(...)`
- 查询改写：`cjk_expand_query` 把中日韩字符拆成 `NEAR(...)`，特殊符号 token 自动加引号
- 召回后做内存过滤（adapter / project / session_id / chunk_type / 时间窗）+ 新近度加权

FTS5 的优点是快、跨 IDE 统一；短板也明显：

1. 纯关键字匹配，没有语义相似度，概念性提问（"上次讨论架构那次"）容易漏召。
2. 索引滞后于真实 jsonl 写入时，刚刚发生的会话可能搜不到。
3. 用户明确知道"我在某天某文件里讲过 X"时，FTS5 给不出文件/行号视角。
4. 无 regex 支持。

业界主流 coding agent（Claude Code / Codex / Cursor）的默认习惯是
`rg` / `fd` / `jq` 直接对源文件操作，灵活度高。memex 当前 MCP 工具集**没有**这类
兜底能力，也没有暴露 raw jsonl 读取入口。

本设计提案给 MCP 增加三个 `raw_*` 工具，**作为 FTS5 的兜底**，不替代主路径。

## 2. 目标与非目标

### 目标

- 当 FTS5 召回为 0 或明显不相关时，LLM 可走 raw 工具直接扫原始 session 文件。
- 支持 regex / 字面量两种模式，支持大小写、上下文行、时间窗、adapter/project 过滤。
- 工具结果尽量映射回 `session_id` + `memex://session/<id>` deep link，方便后续 `get_session`。
- 沙箱化：raw 工具只能访问 memex 已纳管的源目录，不允许成为通用 grep。

### 非目标

- 不引入向量检索 / embedding（另立提案）。
- 不重写现有 FTS5 路径。
- 不暴露任意路径读写；不支持写操作。

## 3. 总体方案

新增三个 MCP 工具，统一前缀 `raw_*`：

| 工具 | 等价 CLI | 用途 |
|---|---|---|
| `raw_grep` | `rg` | 在原始 session 文件中按字面量/regex 搜内容 |
| `raw_find` | `fd` | 按文件名/路径/mtime/大小定位 session 文件 |
| `raw_read` | `sed -n` / `tail` | 按行号区间读取片段，可选 jsonl 解析 |

实现放在 `crates/memex-core/src/retriever/` 下新增 `raw.rs` 模块；MCP 侧在
`crates/memex-cli/src/commands/mcp/server/tools.rs` 注册三个新 `TOOL_*` 常量与 handler。

### 3.1 后端选型

- **不 shell out** 到系统 `rg` / `fd`，避免环境依赖。
- 用纯 Rust crate：
  - 内容搜索：`grep` + `ignore`（ripgrep 同源 crate）
  - 文件遍历：`ignore::WalkBuilder` 或 `walkdir` + `globset`
  - regex：`regex` crate（已在依赖里）

### 3.2 沙箱（关键安全约束）

**重要前提**：memex 在 ingest 阶段已经把所有 adapter 的原始会话（jsonl / SQLite / 任意格式）
归一化写入本地统一目录：

```
<data_dir>/sessions/<adapter>/<session_id>.md
```

其中 `<data_dir>` 默认 `~/.memex`，由 `MemexConfig.resolved_data_dir()` 解析；
`<adapter>` ∈ `claude_code` / `codex` / `cursor` / `continue` / `opencode`。
每个 md 带 YAML frontmatter：

```yaml
---
session_id: <id>
source: <adapter>
project: <abs path or null>
created: <rfc3339>
---
```

由 `crates/memex-core/src/storage/markdown.rs::write_session_markdown` 统一写入。

**沙箱设计直接收敛到这一个目录**：

- 唯一根路径：`<data_dir>/sessions`
- 所有 raw 工具入参的 `file` 字段必须 `canonicalize()` 后 `starts_with(<data_dir>/sessions)`，
  否则返回 `path_outside_sandbox`。
- 不需要遍历各 IDE 的原始路径（`~/.claude/projects` 等），那是 collector 的事，
  与 raw 检索解耦。
- 天然覆盖所有 adapter（包括 Cursor SQLite —— 它在 ingest 时已被归一化成 md）。

带来的额外好处：
- 文件格式统一为 markdown，行号语义稳定（不像 jsonl 一行一条记录、长度差异巨大）。
- frontmatter 已经把 `session_id` / `source` / `project` 写在文件头部，
  反查零成本，不需要从文件名硬解析（虽然文件名也是 session_id，是双保险）。
- 用户可以直接 `cat` 这些 md 验证，可读性比 jsonl 好。

### 3.3 性能与稳定性

- 每次调用 **5s 硬超时**（`tokio::time::timeout` 或同步线程 + channel）。
- `limit` 上限：`raw_grep` 200 条命中，`raw_find` 500 个文件。
- `context` 上下文行：默认 2，最大 10。
- 复用 `mcp_call_log` 记录调用，便于事后审计与统计。

## 4. 接口契约

### 4.1 `raw_grep`

```jsonc
// 入参
{
  "query": "redis pipeline",       // 必填
  "regex": false,                   // 默认 false（字面量）
  "case_sensitive": false,          // 默认 false
  "adapter": "claude-code",         // 可选，限定 IDE
  "project": "/abs/path/to/repo",   // 可选，前缀匹配 cwd
  "after": "2026-06-01",            // 可选，文件 mtime ≥
  "before": "2026-06-30",           // 可选，文件 mtime ≤
  "context": 2,                     // 命中前后行数，默认 2，最大 10
  "limit": 20,                      // 命中数上限，默认 20，最大 200
  "files_only": false               // true 时仅返回去重后的 session 列表（rg -l）
}

// 返回
{
  "hits": [
    {
      "session_id": "0a1b2c…",
      "adapter": "claude-code",
      "project": "/Users/.../memex",
      "file": "/Users/.../projects/-Users-.../0a1b2c.jsonl",
      "line": 142,
      "timestamp": "2026-06-18T03:21:04Z",
      "role": "user",
      "snippet": "…前 2 行 / 命中行 / 后 2 行…",
      "deep_link": "memex://session/0a1b2c…"
    }
  ],
  "truncated": false,
  "elapsed_ms": 38
}
```

错误码：
- `invalid_regex` —— `regex=true` 但 query 编译失败
- `path_outside_sandbox` —— 内部路径解析失败（理论上不会被入参触发）
- `timeout` —— 超过 5s
- `too_many_hits` —— 内部命中数已超 limit*5，提前截断（在 `truncated: true` 中体现）

### 4.2 `raw_find`

```jsonc
// 入参
{
  "name_pattern": "*.jsonl",        // glob 或 regex（视 regex 开关）
  "regex": false,
  "adapter": "cursor",              // 可选
  "project": "...",                 // 可选
  "after": "2026-06-01",            // 文件 mtime ≥
  "before": "2026-06-30",
  "min_size_kb": 0,
  "max_size_kb": null,
  "limit": 50                       // 默认 50，最大 500
}

// 返回
{
  "files": [
    {
      "path": "...",
      "adapter": "claude-code",
      "session_id": "0a1b2c…",
      "size_bytes": 84231,
      "mtime": "2026-06-29T11:02:00Z",
      "deep_link": "memex://session/0a1b2c…"
    }
  ],
  "truncated": false,
  "elapsed_ms": 12
}
```

### 4.3 `raw_read`

主要给 `raw_grep` 命中后"再多看 20 行上下文"用，避免 LLM 自己拼 `head/tail`。

```jsonc
// 入参（session_id 与 file 二选一，优先 session_id）
{
  "session_id": "0a1b2c…",
  "file": "/abs/path",
  "start_line": 100,                // 1-based 闭区间
  "end_line": 200,
  "parse_jsonl": true               // 默认 true：每行解析为 {role, content, timestamp}
}

// 返回
{
  "file": "...",
  "session_id": "...",
  "lines": [
    { "line": 100, "role": "user", "timestamp": "...", "content": "…" }
  ],
  "truncated": false                 // true 表示 end_line 超过文件实际行数
}
```

约束：
- `end_line - start_line` 最大 500，否则 `range_too_large`。
- `parse_jsonl=true` 时若某行不是合法 JSON，降级返回 `{ line, raw: "…" }`。

## 5. session_id 反查

由于所有 adapter 都被归一化到 `<data_dir>/sessions/<adapter>/<session_id>.md`，
session_id 反查变成两条等价路径：

1. 文件名直接 = `<session_id>.md`，剥后缀即可
2. 文件头 frontmatter 的 `session_id:` 字段（更权威，防止文件名被改）

实现优先读 frontmatter，文件名作为兜底校验。`source` / `project` 同样从 frontmatter 取，
不需要再维护各 adapter 的命名约定表。

raw 工具天然覆盖全部 adapter（包括 Cursor）。

## 6. SKILL.md / MCP tool description 文案

工具描述里要清楚标注"兜底"语义，避免 LLM 把它当首选：

> `raw_grep`: Fallback raw-file content search when `search_memory` returns no useful
> results. Scans original session jsonl files using literal or regex match.
> **Prefer `search_memory` first** — only use this when FTS5 cannot find what the
> user describes, or when the user explicitly asks for regex / file-line view.

`app/skills/claude-code/SKILL.md`（以及其他 IDE 的 SKILL.md）的"场景"列表追加：

```
### 场景 6：FTS5 miss 时的原始文件兜底 → raw_grep / raw_find / raw_read

触发：用户明确说"我记得讲过 X 但搜不到" / "search_memory 没结果但应该有"
     / "按文件找最近某个 session" / 需要 regex / 按 mtime 找文件。
顺序：先 search_memory；返回 0 条或明显不相关时，再 raw_grep。
回链：raw_grep 命中后，用 session_id 调 get_session 拿完整上下文。
```

global CLAUDE.md 里"禁止用 grep/Read 替代 MCP"的规则保留 —— 因为 `raw_grep` 本身
就是 MCP 工具，不冲突；禁止的是 LLM **绕过 memex 直接** grep 用户磁盘。

## 7. 实现拆解

按优先级排：

1. **`raw_grep`（P0）** —— 价值最大，单独可用
   - `crates/memex-core/src/retriever/raw.rs`：`raw_grep(req: RawGrepRequest) -> RawGrepResponse`
   - 沙箱白名单收集函数
   - jsonl 行解析 helper（提取 role / timestamp）
   - 单元测试：临时目录构造假 jsonl，覆盖 regex / 字面量 / context / files_only / 越界路径
2. **`raw_find`（P1）**
   - 复用沙箱白名单
   - `ignore::WalkBuilder` 遍历，glob/regex 双模
3. **`raw_read`（P1）**
   - 简单 BufRead，按行数 skip / take
   - 单元测试覆盖 jsonl 解析降级
4. **MCP 注册**
   - 在 `tools.rs` 加 `TOOL_RAW_GREP` / `TOOL_RAW_FIND` / `TOOL_RAW_READ`
   - dispatch 分支 + JSON schema
5. **SKILL.md 文案更新**（四个 adapter 的 SKILL.md + 顶层 `app/SKILL.md`）
6. **README 更新**（列出新 MCP 工具）

## 8. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| LLM 把 `raw_grep` 当首选，绕过 FTS5 | 性能退化（每次扫文件） | 工具描述强调"fallback"；后续可在 `mcp_call_log` 加比例监控 |
| 大 jsonl 文件 grep 慢 | 工具调用超时 | 5s 硬超时；`limit*5` 内部截断 |
| 沙箱被绕过（symlink） | 越权读用户磁盘 | `canonicalize()` 后再做 prefix check；不跟随 symlink |
| jsonl schema 因 adapter 升级变化 | role/timestamp 解析失败 | parse 失败时降级到 `raw` 字段，不影响主功能 |

## 9. 后续可能扩展（不纳入本次）

- `raw_jq`：内置 jq 表达式过滤 jsonl 行
- 语义检索（embedding）作为另一条兜底路径
- raw 工具的命中结果反向触发 FTS5 重建（"为什么这条没被索引"诊断）
